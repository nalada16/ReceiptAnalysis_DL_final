## 實驗一：商品語意分群方法對照

### 為什麼用這些指標

商品分群是**非監督**任務，沒有直接準確率。我用成員 A 的 **6 類消費標籤當外部基準**
（好的商品群不該混到不同消費類別），再配合內部指標：

| 指標 | 類型 | 意義 | 越高越好 |
|---|---|---|---|
| purity | 外部 | 每群多數類別佔比 | ✓ |
| homogeneity | 外部 | 群內是否單一類別 | ✓ |
| NMI / ARI | 外部 | 分群與 6 類的整體一致性（**會懲罰群數遠多於類別數**） | ✓ |
| silhouette | 內部 | 群內緊密、群間分離 | ✓ |
| noise_ratio | 結構 | HDBSCAN 判為離群的比例 | ✗（低較好） |

> ⚠️ 關鍵理解：商品群（~108 群）比 6 類**細很多**，所以 NMI/ARI 對細分群天生偏低，
> 不代表分群差。判斷細分群品質要看 **purity / homogeneity / silhouette**；
> NMI/ARI 只在「想還原 6 類」的粗粒度情境才是主指標。

### 設計：兩種固定粒度做公平比較

- **細粒度 K=108**：商品群，與 HDBSCAN 自動找到的群數同級 → 公平比 HDBSCAN vs KMeans vs Agglo。
- **粗粒度 K=6**：對齊 6 類消費 → 檢驗 embedding 能否還原類別。

### 結果

| config | n_clusters | noise | coverage | purity | homog. | NMI | ARI | silhouette |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| **細粒度（商品群，~108）** |||||||||
| raw768 + HDBSCAN | 85 | **0.32** | 0.68 | 0.993 | 0.962 | 0.32 | 0.02 | 0.699 |
| raw768 + KMeans(108) | 108 | 0 | 1.00 | 0.992 | 0.965 | 0.28 | 0.01 | 0.384 |
| raw768 + Agglo(108) | 108 | 0 | 1.00 | 0.992 | 0.967 | 0.28 | 0.01 | 0.389 |
| PCA30 + HDBSCAN | 83 | **0.34** | 0.66 | 0.992 | 0.963 | 0.33 | 0.02 | 0.693 |
| PCA30 + KMeans(108) | 108 | 0 | 1.00 | 0.991 | 0.965 | 0.27 | 0.01 | 0.449 |
| PCA30 + Agglo(108) | 108 | 0 | 1.00 | 0.992 | 0.968 | 0.28 | 0.01 | 0.433 |
| **UMAP5 + HDBSCAN（採用）** | 110 | **0.069** | 0.93 | 0.991 | 0.951 | 0.27 | 0.01 | **0.882** |
| UMAP5 + KMeans(108) | 108 | 0 | 1.00 | 0.991 | 0.949 | 0.26 | 0.01 | 0.834 |
| UMAP5 + Agglo(108) | 108 | 0 | 1.00 | 0.991 | 0.950 | 0.26 | 0.01 | 0.833 |
| **粗粒度（對齊 6 類）** |||||||||
| raw768 + KMeans(6) | 6 | 0 | 1.00 | 0.990 | 0.922 | **0.92** | **0.97** | 0.796 |
| PCA30 + KMeans(6) | 6 | 0 | 1.00 | 0.990 | 0.922 | **0.92** | **0.97** | 0.829 |
| UMAP5 + KMeans(6) | 6 | 0 | 0.89 | 0.613 | 0.481 | 0.45 | 0.45 | 0.431 |

### 三個可寫進報告的結論

1. **BERT embedding 品質很高**：未降維 / PCA 直接 KMeans(K=6) 就能還原 6 類消費，
   **ARI 0.97、NMI 0.92**。代表成員 A 的 embedding 已把消費語意編碼得很好。

2. **商品群任務（C 的主任務）最佳組合 = UMAP5 + HDBSCAN**：
   - silhouette **0.882**（全場最高，遠勝 raw/PCA 的 0.38–0.45）。
   - noise 僅 **6.9%**，coverage 93%；而 raw768/PCA 上的 HDBSCAN noise 高達 **32–34%**
     （高維空間密度估計失準）→ **UMAP 降維把 noise 砍掉約 5 倍**，這就是為什麼要降維。
   - 自動決定群數，不必預設 K；purity 0.99 表示商品群幾乎不跨消費類別。

3. **UMAP 是雙面刃**：它讓細分群表現最好，卻**傷害粗分群**——UMAP5+KMeans(6) 的
   ARI 只有 0.45（vs raw 的 0.97）。因為 UMAP 5 維強化局部微結構、犧牲全域 6 類大結構。
   → 啟示：**要 6 類分類別用 raw/PCA，要商品微群用 UMAP**；兩者目的不同。

**最終選擇：UMAP5 + HDBSCAN**（細商品群，供步驟 2/3 通膨拆解使用）。

## 實驗二：通膨拆解的替代方案對照

通膨拆解無「準確率」（兩項拆解 residual 恆為 0），但**設計選擇會大幅改變結論**。
比較兩個替代分支（全使用者合計，各群取自身最早/最晚月）：

| config | n_groups | total_delta | price(2項) | qty(2項) | price(3項) | qty(3項) | interaction(3項) |
|---|---:|---:|---:|---:|---:|---:|---:|
| **group=exact（採用）** | 95 | −1227 | 1488 | −2715 | 2624 | −2715 | −1136 |
| group=cluster | 137 | −7656 | 3335 | −10991 | 19217 | −10991 | −15882 |

### 結論

1. **分群鍵：exact 才可靠**。改用語意群（cluster）雖覆蓋率更高（137 vs 95 群），但
   total_delta 從 −1227 暴增到 −7656、交互項巨大（−15882）——因為語意群把**不同單價的
   商品混在一起**，使 P0/P1 失真、量價效應被嚴重高估。
   → **通膨拆解採 exact（同品名+店名）**；語意群僅用於商品探索，不用於量價拆解。

2. **兩項 vs 三項拆解一致**：兩項的價效應 = 三項價效應 + 交互項
   （exact：2624 + (−1136) = 1488 ✓）。兩項把交互併入價效應、公式簡潔；
   報告若要強調「又漲又少買」的交互效果，可改報三項（程式已同時輸出兩種）。

## 實驗三：投影片「Layer3 比較對象」四列（對應簡報）

對應簡報那張「任務二 Layer3：消費增量分析比較對象」。四個方法用相同外部基準（6 類標籤）評估。
重跑：`uv run python step1c_slide_baselines.py`（第 3、4 列取自實驗一的 UMAP5 結果）。
原始數據：`outputs/exp_slide_baselines.csv`。

| 方法 | 類型 | n_clusters | noise | coverage | purity | homog. | NMI | silhouette |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| Regex 關鍵字比對 | Rule-based 下限 | 19 | **0.561** | 0.439 | 0.977 | 0.922 | 0.44 | 0.258 |
| TF-IDF + HDBSCAN | 傳統 ML 對照 | 74 | **0.361** | 0.639 | 0.986 | 0.925 | 0.24 | 0.708 |
| BERT Embedding + K-Means | 消融實驗 | 108 | 0.000 | 1.000 | 0.991 | 0.949 | 0.26 | 0.834 |
| **BERTopic (BERT + HDBSCAN) — Ours** | Ours | 110 | **0.069** | 0.931 | **0.991** | **0.951** | 0.27 | **0.882** |

### 這張表如何支撐簡報的兩個主張

- **解決「語意辨識不清」**：Regex 關鍵字只能靠人工規則，**覆蓋率僅 43.9%**（56% 品項規則完全
  抓不到，例如手寫菜名、英文品名、變體寫法）；Ours 用 BERT 語意，覆蓋率 **93.1%**，且能把
  「大冰美式／中冰美式／特大冰美式」這類變體歸到同群——這是規則法做不到的。
- **解決「雜訊干擾」**：傳統 TF-IDF + HDBSCAN 的 **noise 高達 36%**（詞頻向量在高維稀疏空間
  密度估計失準）；Ours 經 UMAP 降維後 noise 降到 **6.9%**，silhouette 從 0.708 提升到 **0.882**。
- **對照消融**：BERT + K-Means 雖 coverage 100%，但**強迫每個點進群、無 noise 機制**，會把
  真正的離群品項硬塞進某群；Ours 保留 noise 判斷又維持高 silhouette，更適合真實發票資料。

> ⚠️ 誠實標註：各列 silhouette 是在**各自的特徵空間**算的（Regex 在 BERT 空間、TF-IDF 在
> 詞頻空間、Ours 在 UMAP 空間），跨列的 silhouette 不是嚴格可比；**最穩健的跨方法比較指標
> 是 coverage / noise_ratio / purity / NMI**。

## 設計討論：為什麼三人 pooled 分群、小資料量使用者會不會被犧牲？

> 這是老師很可能追問的方法學問題，含實測數據與答辯說法。

### Q1. 不同人的資料混在一起分群，會不會把個人消費「算」在一起？

不會。要分清楚兩個階段的角色：

- **分群階段＝建一本「商品字典」**：單位是「每一筆品項」，目的是回答「哪些明細其實是同一種
  商品」。商品身份是客觀、與「誰買」無關的（embedding 輸入只有 品名+店名+金額區間，不含
  user_id）。字典本來就該是**公版、跨使用者一致**的——否則 user 0 的「群 3」和 user 1 的
  「群 3」會是不同東西，無法對齊比較。
- **診斷階段（單價/通膨）＝拿字典讀各自的帳本**：step2/step3 的 group key 帶 `user_id`
  （`by_user=True`），每個人的量價效應**分開算**。

→ 結論：**分群 pooled（對，建公共字典）、通膨分人（對，個人行為）**。pooled 不會污染個人
分析，因為每筆被分到哪群只由「那筆自己的內容」決定。

### Q2. A/B 資料量大，會不會主導分群、害 C（資料少又獨特）被丟進 noise？

**理論上會擔心，但實測證明影響很小，且 noise 是良性的。**

各 user 的 noise 比例（`step1_clusters.csv`）：

| user | 筆數 | noise 比例 |
|---|---:|---:|
| user 1（最多）| 1505 | 5.2% |
| user 0 | 680 | 8.7% |
| user 2（最少）| 428 | 10.3% |

小資料量者 noise 確實略高（約 2 倍），但深入看機制：

- **user 2 的 noise 品項，100% 都是「全體出現 < 10 次」**（min_cluster_size=10），其中
  54.5% 只出現過 1 次。
- **全體出現 ≥10 次的品項，99% 都成功分群**（不論誰買）。
- **沒有巨群輾壓**：群大小中位數 18、最大 133，最大的 5 群只佔 14.7% 的點。HDBSCAN 在密度
  階層樹上抽群，不同密度的群位於不同子樹，**A/B 的大群不會壓制 C 的小群**。

→ 機制澄清：C 的 noise **不是被 A/B「主導」造成的**，而是 **C 自己那些品項出現次數太少**
（內在稀有性，單一使用者資料也會發生）。

### 由此得到的兩個定論

1. **可以放心三人 pooled 分群，重複資料影響不大**：同品名→同群（重複只是互相加強），
   HDBSCAN 自適應密度、不跨區壓制。
2. **這個 noise 是良性的，不是公平性 bug**：會變 noise 的都是「出現 < 10 次」的品項，而通膨
   拆解本來就要求 ≥5 次——買一兩次的東西本來就無法追蹤單價。「稀有→noise」剛好濾掉不可
   分析的資料。
   - ⚠️ 曾考慮「對去重商品種類分群」來消除頻率偏差，但因 noise 來自**稀有**而非**頻率灌水**，
     去重無效且更糟（稀有品項仍無鄰居，原本靠重複撐密度的反而失去鄰居），已放棄此做法。

> 唯一要寫進限制的，只是「**低頻 / 獨特品項無法納入商品群分析**」這個客觀邊界（見
> `README_memberC.md` 第 5 節）。

## 實驗五：per-user 全分開管線（分開分群 → 分開增量分析）

> 不只比分群品質（實驗四是理論+分群指標），這裡**真的把整條下游跑一遍**：
> 三人各自分群 → 各自做增量分析，看會不會出問題。
> 程式與產出都在獨立資料夾 `per_user_pipeline/`（不與主流程混）。
> 重跑：`cd per_user_pipeline; uv run python pu_step1_clustering.py; uv run python pu_step3c_increment.py`

### 5.1 分群品質：per-user vs pooled（限定該 user）

| user | 筆數 | 群數 pooled→solo | homogeneity | silhouette | noise |
|---|---:|---|---:|---:|---:|
| user 0 | 680 | 73 → 33 | 0.92 → 0.86 | 0.89 → 0.85 | 0.09 → 0.09 |
| user 1 | 1505 | 89 → 61 | 0.98 → 0.95 | 0.92 → 0.91 | 0.05 → 0.05 |
| user 2 | 428 | **59 → 8** | 0.93 → 0.89 | 0.79 → 0.75 | 0.10 → 0.03 |

- 反直覺：小 user 單獨跑 noise 不升反降（10%→3%），但這是**粒度崩塌**的假象——
  群數從 59 暴跌到 8，把不同商品擠成粗團塊，homogeneity/silhouette 同步下降。

### 5.2 下游增量分析：可分析類型數（清理+一致性+每類型≥10筆後）

| user | 筆數 | pooled(step3c) | per-user(pu) |
|---|---:|---:|---:|
| user 0 | 680 | 19 | 25 |
| user 1 | 1505 | 54 | 53 |
| **user 2** | 428 | **8** | **4** |

- 大資料量者（0、1）：分開跑可行，可分析類型數相當（user 0 甚至略多）。
- **小資料量者（user 2）：可分析類型砍半（8→4）**，且 4 類**全是瓶裝水/文具**
  （多喝水、泰山、味丹、a4 簿），完全代表不了真實消費 → 增量分析失效。

### 5.3 跨人破碎度（per-user 的致命傷）

- 被 ≥2 人購買的商品種類：13 種（佔 2.3% 金額）。
- pooled：100% 落在同一群（跨人可比）✅；per-user：0%（定義上不可能同群）❌。

### Insight（可寫進報告）

1. **技術上能跑，但對小資料量使用者不可靠**：user 2 分開跑後只剩 4 個可分析類型，
   增量診斷形同失效。
2. **粒度崩塌**：資料不足 → 細商品群解析不出來 → 退化成粗團塊（user 2: 59→8 群）。
3. **失去跨人可比**：分開跑無法定義「同一商品」跨人比較。
4. **最終決策有實證**：主流程採 **pooled 分群（公共字典）+ 分人增量分析（step3c）**，
   不是事後辯解，而是「試過分開、對小 user 會崩」的實驗結果。

## 主交付：個人增量分析（step3c，Layer 3 的答案在這）

> Layer 3 的「結果」不在上面的對照實驗，而在 `step3c_personal_inflation.py`。
> 重跑：`uv run python step3c_personal_inflation.py`；圖：`outputs/step3c_user{0,1,2}.png`。

定義：解釋「這個月」比「平常月均」多花的錢，落在哪些**類型商品**，拆成
**變貴**(50元珍奶→70元珍奶) vs **買更多**(每月5杯→10杯)。類型 = 語意商品群。

清理三層（讓單價可信）：① 剔除佔位品名（代收/塑膠袋/餐飲費…）② 類型一致性
（群內單價 p90/p10 ≤ 6）③ 每使用者每類型 ≥ 10 筆。

### Insight

- **個人通膨是品項分化的，非齊漲**：user 1 清燉牛肉 +11%、清爽沙拉飯 +9%，
  但原味波士頓 −6%、紅茶持平 → 「東西越來越貴」不普遍成立。
- **多花的錢常是「買更多」而非「變貴」**：例 user 1 清燉牛肉本月多花 1003 元，
  其中買更多 860、變貴僅 143（從每月 2.25 份暴增到 6 份）。
